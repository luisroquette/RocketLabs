## From problem to product

<p align="center">
  <img src="./assets/lab-loop.svg" alt="RocketLabs cycle: observe, build, validate, open and evolve" width="100%" />
</p>

1. **Observe** — start with a real, specific problem.
2. **Build** — turn the workflow into software, a skill or infrastructure.
3. **Validate** — test the primary path and state limitations honestly.
4. **Open** — publish code, documentation and a clear entry point.
5. **Evolve** — learn from use and feed the next version.

## How this lab works

- **Every project is independent.** Download only what you need.
- **The catalog is the navigation source.** [`projects.json`](./projects.json) holds the canonical list.
- **The catalog requires no keys.** Each project documents its own variables and integrations.
- **No invented claims.** Concept demos are identified and limitations stay visible.
- **Explicit licensing.** Public code may only be reused when its license permits it.

### Add or update a project

Edit [`projects.json`](./projects.json), then run:

```bash
node scripts/render-readme.mjs
node scripts/validate-catalog.mjs
```

The first command updates the Portuguese and English tables. The second rejects
duplicate links, invalid fields and missing images.

## Security and support

- Found a possible vulnerability? Follow [`SECURITY.md`](./SECURITY.md) and never publish secrets in an issue.
- Need to understand the support level? Read [`SUPPORT.md`](./SUPPORT.md).
- Product-specific problems belong in that product's repository.

RocketLabs is a free catalog maintained on a best-effort basis. There is no SLA,
compatibility guarantee or mandatory individual support.

## Principles

> AI is only useful when it becomes a dependable capability in someone's hands.

RocketLabs prioritizes autonomy, concrete utility, honest documentation,
understandable architecture and data control. Not every experiment becomes a
product; everything listed here already has something real to explore, install
or study.

## Follow the work

If a project solves a problem for you:

1. Open its repository and watch the demo.
2. Read the requirements and limitations.
3. Give it a ⭐ so you can find it later.
4. If you find a reproducible problem, open an issue in the correct project.

Aggregate discovery metrics are preserved in the
[weekly traffic history](./metrics/README.md).
